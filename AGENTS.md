
# DPI GUI — Спецификация проекта (Прочти перед началом работы)

### 00. Глобальная документация (читать ОБЯЗАТЕЛЬНО)
> **Перед любой работой — прочитать и учитывать документацию из:**
> 1. `D:\Projects\docusaurus-starter\docs\Sega Mega Note\Моя картотека\software\настройки\global_ai_docs` — глобальные правила и контекст проекта.

## 1. Архитектура и Разрешения
* **Фронтенд:** React + TypeScript + TailwindCSS + Vite.
* **Бэкенд:** Rust + Tauri v2.
* **Права Администратора:** WinDivert (драйвер обхода) требует прав администратора для старта. В `src-tauri/build.rs` вшит манифест Windows, который автоматически запрашивает права при запуске. 

## 2. Установка (perMachine) и Автообновление
Приложение работает от имени Администратора. Это накладывает жёсткие требования на процесс установки:
- В `tauri.conf.json` установлен `"installMode": "perMachine"`.
- **Почему нельзя использовать AppData для установки exe:** Если установить `currentUser` (в `%LOCALAPPDATA%`), то установщик, запущенный через elevated-приложение при автообновлении, унаследует права админа и установит новую версию в папку админа, а не пользователя. В результате бинарник не обновится! **Никогда не убирай perMachine.**

## 3. Блокировка файлов (WinDivert64.sys)
Драйвер ядра WinDivert блокирует свой `.sys` файл при работе. Жёсткое `taskkill /F winws.exe` **не выгружает драйвер из памяти**! Из-за этого установщик или автообновление упадут с ошибкой `os error 32` (Файл занят).
- В `src-tauri/src/process.rs` функция `stop_winws()` **всегда** должна выполнять `sc stop WinDivert` (а также `WinDivert1.4` и `windivert`) и делать паузу на выгрузку.
- В `src-tauri/installer.nsh` в хуках `NSIS_HOOK_PREINSTALL` и `NSIS_HOOK_PREUNINSTALL` также прописана остановка службы, чтобы ручная установка поверх работающего обхода не падала. Не удаляй эти хуки.
- Приложение гасит обход на `on_window_event` (закрытие окна) в `main.rs`, чтобы корректно освободить драйвер.
- **Честность статуса обхода (не возвращай фолбэк-ложь):** `is_winws_running()` в `process.rs` отвечает «активен» ТОЛЬКО при живом процессе `winws.exe` (точное совпадение имени). Служба WinDivert может пережить смерть winws (падение/убитое приложение), но загруженный драйвер сам ничего не обходит — никогда не считай её признаком активности, иначе после перезапуска UI лжёт зелёным «ПРОЦЕСС АКТИВЕН» на мёртвом обходе (баг 25.10.26). Остаточную службу при старте выгружает `cleanup_stale_windivert()` из `init_app`.

## 4. Файловая система и Данные
### 4.1 Бандл (`bin/`)
В установочную директорию (в `Program Files/DPI_GUI/bin/`) копируются **исполняемые** файлы:
- `winws.exe`
- `WinDivert64.sys` и `WinDivert.dll`
- Фейки: `quic_*.bin`, `tls_*.bin`.

### 4.2 Пользовательские данные (`AppData/Local/DPI_GUI/`)
Списки и настройки хранятся в защищённом каталоге профиля пользователя, чтобы они пережили обновление версии. Путь задаёт `config::get_app_dir()` через `dirs::data_local_dir()` — именно **Local**, не Roaming (реальная папка проверена 27.10.26; не меняй на Roaming):
- `config.json` и `profiles.json` (создаются при инициализации).
- Папка `lists/` (кастомные `list-general.txt`, `list-exclude.txt`).
- `list-google.txt` и `default-exclude.txt` — генерируются автоматически в `AppData` при каждом запуске (из `config.rs`). Не убирай их генерацию, иначе обход будет падать с ошибкой отсутствия файла хостлиста.

## 5. Нюансы диагностики (`diagnostics_probe.rs`)
В коде диагностики есть критические места, которые были исправлены ранее — не возвращай старые ошибки:
- **Проверка прав:** Осуществляется через `net session` (без ключей). Команда `net session /fo list` не работает в обычных ОС и всегда возвращала ложное отсутствие прав `ADMIN=0`.
- **Проверка WinDivert:** Тест драйвера запускается скрытым процессом (`winws`). **Никогда не оборачивай пути в кавычки** прямо в `Command::args` (`"--hostlist=\"...\""` — неправильно, Rust сам экранирует аргументы). Это ломало путь и выдавало ложный статус `WINDIVERT=FAIL`.

## 6. Домен-монитор ошибок сети (`domain_monitor.rs` + `fake_payloads.rs`)
- **Фильтр фейков winws (инвариант, инцидент 27.10.26 — не удаляй):** winws шлёт 8–11 подставных копий на каждый подменяемый пакет (`--dpi-desync-repeats`), а перед ClientHello — seqovl-паттерн. Монитор — пассивный сниффер и эти пакеты видит: без фильтра они считались ретрансмиссиями/QUIC Initial, а SNI-коллектор лочился на SNI ИЗ ФАЙЛА-ФЕЙКА (`tls_clienthello_max_ru.bin` несёт SNI `www.onetrust.com`, `*_www_google_com.bin` — `www.google.com`), и список «Ошибки сети» заполнялся фантомами. `fake_payloads.rs` грузит байты фейков из аргументов запуска winws (SSOT: `spawn_winws` передаёт те же `final_args` в `start_domain_monitor`) и отсекает payload с общим префиксом ≥ 32 байт с любым блобом. Мonitor запускается только из `spawn_winws` (после старта winws) и гасится в `stop_winws` — источник аргументов всегда актуален.
- **Владелец UDP-сокета:** QUIC-события берут процесс через `process_owner::udp_owner_name_and_exe()` (UDP-таблица, поиск по локальному порту — у UDP нет удалённой пары). TCP-события ищут по 4-tuple через `owner_name_and_exe()` — не подменяй один другим, это ложная атрибуция.

## 7. Подбор DNS и вердикт гео-блока (`dns_pick.rs`, `site_probe.rs`)
- **Вердикт «рабочий DNS» — только по сквозной HTTPS-пробе (`http_via_ip`, SSOT).** Эвристики по ownership IP («IP вне диапазонов Google = проксирует») запрещены — это хардкод под один сайт, лгущий на всех остальных (кейс Patreon 01.11.26: Cloudflare 1009 = отказ самого сайта, VPN-кейс). Детали и три слоя отказа — `docs/blocks.md` §3.
- **Вердикт шлюза DoH-сервиса — только сквозная HTTPS-проба через шлюз (`http_via_ip`; правка 09.11.26 — не откатывай к TCP).** TCP-живость вердиктом не считается: она соврала на openrouter.ai (сайт открывался только через 2 из 7 шлюзов пула eu.geohide.ru). Мина «шлюз соврёт своим 200» обезврежена валидацией сертификата в SSOT-пробе: чужой 200 без валидного сертификата сайта = `BadCert`, не `Ok` (passthrough-фронтинг показывает оригинальный сертификат и настоящую страницу → `Ok`). Пороги (`aggregate_gateway_set`): `GatewayAlive` — сайт открывается через ≥ половины шлюзов пула; `GatewayPartial` — меньше половины (warn «надёжнее VPN»); ни один — `GatewayDead`/`SiteBlocked`. «Применить» во вкладке Браузер берёт только подтверждённый пробой IP (`fronting_ips`), не `resolved[0]` (в кейсе 09.11.26 тот был мёртв). Живой Gateway остаётся рекомендацией для посессионных гео-блоков, даже если честные резолверы дают SiteBlocked.
- **Контрольная проба С обходом** (`bypass_on_control_probe`): чистое окно видит только RST (DPI), отказ сайта (403/ServiceRestrict) проявляется лишь с восстановленным обходом — отчёт ведёт с «САЙТ САМ ОГРАНИЧИВАЕТ — VPN», `decide()` не советует починку. `BlockPage` отказом сайта не считается.
- **JS-оболочка = Unverified, не Open (инцидент 08.11.26 — не откатывай):** живой 200 от SPA-оболочки без маркеров ограничения и с видимым текстом < 200 байт (`UNVERIFIED_MIN_VISIBLE` в `site_probe.rs`) — это `HttpResult::Unverified` («доступность после входа не подтверждена»), а НЕ «открывается»: у aistudio ограничение рисуется JS'ом только после входа в аккаунт (замер до прогона: aistudio=36B, google=827B, github=6800B; порог менять после живых прогонов нельзя). HTTP-пробы dns_pick идут в чистом окне (`OffWindowGuard` в `run_pick`) — с включённым winws проба видит только «успех».
## 8. Прокси-движок и вкладка «Канал» (`proxy_core.rs`, `reserve.rs`, `ChannelTab.tsx`)
Приложение держит свой интернет-канал на **одном** `mihomo.exe` из `bin/` (proxy-only, TUN off, ноль внешних зависимостей). Порт канала **7897** (mixed), REST API **9097**. Переключение режима = рестарт ядра с другим конфигом; первый запуск канала гасит Koala Clash (`taskkill`), наша — единственный владелец имени `mihomo.exe` в системе.
- **Режимы:** `off` / `paid` / `reserve` — `channel_set`/`channel_status` в `main.rs` → бизнес-логика в `proxy_core::channel_set`. Гейты ДО убийства Koala: «paid» без активного профиля → честная ошибка; «reserve» без WG-кредов → ошибка.
- **ПРИНЦИП ДАННЫХ (не нарушай):** в репо/бандл едет только публичное — `src-tauri/defaults/reserve_template.yaml` (плейсхолдеры `__PRIVATE_KEY__` и т.п. вместо секретов) и `defaults/igareck_*.yaml` (публичная подписка пула нод). ЛИЧНОЕ юзера — платные профили (`AppData/proxy/paid_profiles/` + реестр `paid_profiles.json`) и WG-ключи (`AppData/proxy/wg_creds.json`) — попадает в AppData ТОЛЬКО импортом на его машине и никогда не входит в ресурсы/логи/статусы (статус кредов не отдаёт приватный ключ).
- **Ensure-паттерн (владелец):** `proxy_core::ensure_proxy_files` при каждом запуске жёстко перезаписывает шаблон и провайдеров в `AppData/proxy/` из встроенных defaults (правки едут релизами), тихо мигрирует старые `paid_source.yaml`/`reserve_profile.yaml` в новые списки (идемпотентно), перегенерирует `reserve_profile.yaml` из шаблона+кредов.
- **Запасной канал:** WG-outbound Proton заворачивается в ноду-такси пула через `dialer-proxy` (fallback-группа `TR`); `reserve.rs` — гард самолечения: 204×3/60с, лечение = provider-healthcheck → alive → PUT `/proxies/TR` → пауза 8с (холодный WG-handshake греется ~10с — первый 204-фейл после старта/смены ноды НЕ ложный отказ!). Нюанс mihomo: per-node `/proxies/{name}/delay` = 404, только provider-endpoint + healthcheck. DNS-пара `dns.google`+`1.1.1.1` обязательна (один заблокированный DoH = все ноды «мертвы»); у WG-outbound НЕ возвращай `remote-dns-resolve`.
- **Генерация платного:** `generate_paid_config` патчит строки АКТИВНОГО профиля юзера (порты + `tun.enable:false` только внутри tun-блока по first-level ключам — `dns.enable` не трогать), вставки после поиска, не по жёстким индексам.
- Парсер WG .conf (`reserve::parse_wg_conf`) покрыт тестами `wg_conf_tests` (Proton-style, PSK, IPv6-endpoint, честные ошибки) — при правке держи их зелёными.

## 9. Правило: ТОЛЬКО стабильные каналы (20.11.26, прямое требование юзера)
Цель приложения — **круглосуточный** доступ (aistudio, Firefly/Mixamo, YouTube). Это главная мера любого канала, важнее «бесплатности» и новизны протокола.
- **В селектор каналов включаются только каналы, выдержавшие суточную проверку стабильности** (живые пробы утром/днём/вечерним пиком/ночью). Канал, который лежит в вечерний пик — НЕ решение задачи, каким бы рабочим он ни был ночью (кейс WARP MASQUE 20.11.26: ночью warp=on/aistudio 200, вечером пул такси 0/240 живых — канал бесполезен для цели).
- **Нестабильный канал = только резерв с честной меткой в UI** («резерв/экспериментальный»), никогда не основной и не подача «проблема решена».
- Новый канал считается стабильным только после суточного прогона с автоматическими пробами; до этого в отчётах/статусах честно писать «стабильность не подтверждена».
- **Приоритет №1 — стабильность/круглосуточность; приоритет №2 — обход геоблоков (aistudio, openrouter и т.п.).** Сначала канал обязан быть круглосуточным (пусть даже без гео-выхода), гео-возможности — надстройка над стабильным каналом.
- Сейчас стабильный канал — платный (`paid_source`). WARP MASQUE (такси igareck) — резерв с непредсказуемой доступностью.
