
# DPI GUI — Спецификация проекта (Прочти перед началом работы)

> ⚠️ ВНИМАНИЕ: Основные абстрактные правила (создание релизов, скрипты сборки, автообновления) лежат в `docs/BASE_GUIDELINES_FOR_ALL_PROJECTS.md`. Здесь описаны **только специфичные для DPI GUI** правила и нюансы архитектуры.

## 1. Архитектура и Разрешения
* **Фронтенд:** React + TypeScript + TailwindCSS + Vite.
* **Бэкенд:** Rust + Tauri v2.
* **Права Администратора:** WinDivert (драйвер обхода) требует прав администратора для старта. В `src-tauri/build.rs` вшит манифест Windows, который автоматически запрашивает права при запуске. 

## 2. Установка (perMachine) и Автообновление
Приложение работает от имени Администратора. Это накладывает жёсткие требования на процесс установки:
- В `tauri.conf.json` установлен `"installMode": "perMachine"`.
- **Почему нельзя использовать AppData для установки exe:** Если установить `currentUser` (в `%LOCALAPPDATA%`), то установщик, запущенный через elevated-приложение при автообновлении, унаследует права админа и установит новую версию в папку админа, а не пользователя. В результате бинарник не обновится! **Никогда не убирай perMachine.**

## 3. Блокировка файлов (WinDivert64.sys)
Драйвер ядра WinDivert блокирует свой `.sys` файл при работе. Жёсткое `taskkill /F winws.exe` **не выгружает драйвер из памяти**! Из-за этого установщик или автообновление упадут с ошибкой `os error 32` (Файл занят).
- В `src-tauri/src/process.rs` функция `stop_winws()` **всегда** должна выполнять `sc stop WinDivert` (а также `WinDivert1.4` и `windivert`) и делать паузу на выгрузку.
- В `src-tauri/installer.nsh` в хуках `NSIS_HOOK_PREINSTALL` и `NSIS_HOOK_PREUNINSTALL` также прописана остановка службы, чтобы ручная установка поверх работающего обхода не падала. Не удаляй эти хуки.
- Приложение гасит обход на `on_window_event` (закрытие окна) в `main.rs`, чтобы корректно освободить драйвер.

## 4. Файловая система и Данные
### 4.1 Бандл (`bin/`)
В установочную директорию (в `Program Files/DPI_GUI/bin/`) копируются **исполняемые** файлы:
- `winws.exe`
- `WinDivert64.sys` и `WinDivert.dll`
- Фейки: `quic_*.bin`, `tls_*.bin`.

### 4.2 Пользовательские данные (`AppData/Roaming/DPI_GUI/`)
Списки и настройки хранятся в защищённом каталоге профиля пользователя, чтобы они пережили обновление версии:
- `config.json` и `profiles.json` (создаются при инициализации).
- Папка `lists/` (кастомные `list-general.txt`, `list-exclude.txt`).
- `list-google.txt` и `default-exclude.txt` — генерируются автоматически в `AppData` при каждом запуске (из `config.rs`). Не убирай их генерацию, иначе обход будет падать с ошибкой отсутствия файла хостлиста.

## 5. Нюансы диагностики (`diagnostics_probe.rs`)
В коде диагностики есть критические места, которые были исправлены ранее — не возвращай старые ошибки:
- **Проверка прав:** Осуществляется через `net session` (без ключей). Команда `net session /fo list` не работает в обычных ОС и всегда возвращала ложное отсутствие прав `ADMIN=0`.
- **Проверка WinDivert:** Тест драйвера запускается скрытым процессом (`winws`). **Никогда не оборачивай пути в кавычки** прямо в `Command::args` (`"--hostlist=\"...\""` — неправильно, Rust сам экранирует аргументы). Это ломало путь и выдавало ложный статус `WINDIVERT=FAIL`.
